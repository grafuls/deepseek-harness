# Agent Note: 侧边栏协作工作区区块复刻 Workspaces 浏览区格式

Status: implemented
Archived: 2026-09-01

[English](2026-08-29-collab-sidebar-section-format.md) | 中文

## Problem

侧边栏本地 Workspaces 浏览区下方的「协作工作区」区块，外观与交互都与上方的浏览区完全不同：一个朴素的 `h2` 标题、一行一行各带独立「打开」按钮（挂载并切换）的工作区行，以及底部的内联创建入口。用户对一个浏览区块期待的全部要素——搜索、视图选项、头部添加入口——要么缺失、要么风格迥异，于是两个角色相同且相邻的面之间毫无视觉与交互对齐可言。

## Decision

现在协作工作区区块复刻 Workspaces 浏览区的格式，作为该单个区块内、本地列表下方的第二个带标签分组——见 [并为一个区块的记录](2026-09-01-collab-sidebar-one-section-two-groups.zh.md)：

- **紧凑的分组工具栏。** 「私有工作区」标签与其控件位于细分隔线下方的一个缩进分组工具栏里，而不是第二个完整的区块头部：可展开的搜索胶囊（展开时收起尾部动作）、相同的视图选项菜单，以及「添加工作区」图标按钮。搜索在本地按名称过滤协作工作区列表。
- **视图选项菜单原样复刻。** 菜单提供浏览区那四项——分组方式「按工作区 / 单列表」、排序方式「手动 / 最近创建」。分组切换每行的前导文件夹装饰，在分组模式下工作区行现在会展开到挂载其中的会话；`updated` 排序按会话自身的最近活动倒序（section-format 时代线上数据只暴露创建时间这一种「最近」信号，会话级别的「最近」随会话浏览一起到来），而 `manual` 保持服务器／工作区顺序——见 [会话浏览记录](2026-08-29-collab-sidebar-section-session-browse.zh.md)。
- **不再有逐行的「打开」按钮。** 点击工作区行现在展开其会话；点击某个会话即直接打开它，因此会话行才是打开入口，正与进入一个默认工作区会话的方式一致——行本身的「挂载并切换」已被 [会话浏览记录](2026-08-29-collab-sidebar-section-session-browse.zh.md) 取代。
- **创建移到工具栏。** 分组的「添加工作区」按钮打开与管理器虚线入口相同的创建对话框（`CreateWorkspace` 增加了可选的触发渲染；虚线按钮仍作为管理器的默认触发）。
- **待处理邀请保留其接收行**，位于可滚动的工作区列表上方；只有既无工作区也无邀请时才显示空态文案。

视图状态（`groupBy`、`orderBy`）存放在共享的 collab 工作区 store 中（默认像浏览区一样为「按工作区 / 最近创建」），并像其他每个动作一样经由同一控制器接缝写入。

## Alternatives considered

- **把协作工作区并入浏览区的树。** 被拒：未打开前协作工作区并不是已挂载的主机工作区，其会话不属于本地会话投影；在区块内保留独立分组（而不是混入树行），在共享格式的同时守住这条边界。
- **完全不做视图选项。** 被拒：需求明确要求与默认区块相同的头部风格并包含视图选项菜单；原样复刻（而非生造面向 collab 的额外排序键）让两个区块保持一致。
- **保留逐行「打开」按钮并在其周围加头部装饰。** 被拒：按钮与行的首要职责重复；浏览区里行本身就是打开入口，因此这里也应如此。

## Consequences

- 协作工作区区块现在与 Workspaces 浏览区视觉与功能上都对等：工具栏、搜索、视图选项、添加、点击即打开全部一致，只有线上特有的内容（成员数、邀请）不同。
- 打开动作可从分组直接触达，不再需要字形按钮，先前的逐行按钮（及其 `open` 词典键）随之移除；管理器面板与其虚线创建入口保持不变。
- 分组仍是可滚动会话列表下方一个有界区块：最高占列高的 40%，自己的行内部滚动，因此列表再长也不会把本地浏览区挤走。
