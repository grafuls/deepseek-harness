# Agent Note：collab 的 git 状态可见性

Status: implemented

[English](2026-09-01-collab-git-state-visibility.md) | 中文

建立在[collab 仓库后端工作区](2026-08-29-collab-repo-backed-workspaces.zh.md)与[collab 异步仓库置备](2026-09-01-collab-async-repo-provisioning.zh.md)之上：本记录描述加入 collab 工作区视图的只读工作树表面。

## 问题

仓库后端工作区的克隆是一个共享的活动树，每位成员的会话都通过挂载的 Host 工作区在其上操作。但成员没有任何只读途径来查看树所处的位置：检出的分支、提交以及共享工作树中是否存在未提交的更改。这些状态只能在宿主机上打开终端才能看到；某位成员留下的脏树直到造成影响才对其他人可见。

## 决策

collab API 的视图构建器在构建视图时读取克隆的工作树状态，并以可选的 `gitState`（`branch`、缩写 `sha` 与 `dirty`）携带在 `CollabWorkspaceView` 上：

- 读取通过对克隆执行三条短 `git` 调用——`rev-parse --abbrev-ref HEAD`、`rev-parse --short HEAD` 与 `status --porcelain`——在单个 `Promise.all` 中于一个五秒的 `AbortSignal.timeout` 内完成，因此缓慢或卡住的文件系统不会拖住整个列表。读取复用共享的无 shell `gitCloneRunner`（与执行克隆的是同一个运行器），因此没有 shell 插值到达进程边界，参数也是固定的。
- `gitState` 在构建视图时计算（列表、获取、创建、重命名、加入），v1 刻意不加缓存：树的状态是每位成员会话写入的结果，陈旧值比略微变重的列表更糟。在健康的检出上三次调用耗时毫秒级；置备式的异步创建与现有路径本就异步，因此只有列表处理器改为 `Promise.all` 遍历视图。
- 只要克隆未落定，或者目录缺失、不是 git 检出、卡住，`gitState` 就不存在——省略该键，而不是空对象。缺失正说明没有可读的树，因此消失的克隆不会显示虚假分支，也不会让每位成员的列表失败。
- 浏览器把状态显示为等宽字体的小芯片，同时出现在工作区行与侧边栏文件夹上：`branch · sha`，脏树使用警告别名色并带前导标记，标题为本地化的「未提交更改」标签。芯片纯展示、由可选字段把关，因此仅命名与克隆中的工作区渲染方式与之前完全一致。
- 通往 API 层的桥是 `WorkspaceSummary.clonePath`，由 workspaces 服务在服务端摘要上设置且从不转发给浏览器；API 视图构建器只用它定位克隆以执行读取。

## 考虑过的备选方案

- **由 workspaces 服务持有 git 状态。** 让 workspaces 服务自己读取 git 并暴露状态。否决：该服务是无 git 知识的纯内存注册表，把它和克隆布局耦合会让克隆语义散落在两个包里；改为由 workspaces 服务只广播它已有的克隆路径，由 API 包执行读取。
- **后台缓存状态。** 用周期更新的程序在带外刷新 `gitState`，让列表无需为读取付费。v1 否决：鲜度正是该表面存在的意义，缓存会引入「树当前在哪里」的第二权威——第一个错误值比每次列表的成本更糟。后续可以无承诺地叠加后台缓存，不改变契约。
- **用一条 `git status` 调用推导全部。** 否决：分支、缩写 HEAD 与脏标记是互不相同的 git 输出；塞进一条命令要么重新引入 shell 插值，要么引入不支持的参数组合。三条固定调用加一个超时才保持运行器接口不变。

## 影响

- 工作区列表现在对每个已落定的仓库后端行执行最多三条短 `git` 调用。健康检出上是亚毫秒读取；目录消失或不可写的克隆报告无 `gitState` 而不是让列表失败，因此不会复活之前的「消失即失败」行为。
- 脏标记把共享树写入暴露出来：某位成员修改了挂载的工作树后，下一次所有成员的视图都会看到警告芯片——这正是通向按会话分支与推送（collab 设置页已允许操作员配置服务端 git 凭据，后续会复用它）的第一步。
- 浏览器表面保持纯展示与本地化；`gitUncommitted` 标签与芯片样式是仅有的 UI 新增，芯片绝不改变行的打开、挂载或生命周期行为。
- 读取要求 collab 网关宿主上有 `git`——与克隆已有的要求相同——因此没有引入新的运维依赖。
