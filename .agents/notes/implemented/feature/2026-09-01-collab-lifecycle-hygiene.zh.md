# Agent Note：collab 仓库生命周期卫生

Status: implemented

[English](2026-09-01-collab-lifecycle-hygiene.md) | 中文

建立在[collab 仓库后端工作区](2026-08-29-collab-repo-backed-workspaces.zh.md)、[collab 异步仓库置备](2026-09-01-collab-async-repo-provisioning.zh.md)、[collab 按会话的工作分支](2026-09-01-collab-session-work-branches.zh.md)与[collab 分支推送](2026-09-01-collab-push.zh.md)之上：本记录覆盖仓库工作流的运维第三段——删除工作区会关掉它的克隆而非残留根目录、成员可以把共享克隆抓到最新、新克隆可以浅克隆，以及每次推送都留下审计线索。

## 问题

仓库后端的工作区已经具备会话分支与服务端推送，但周边的运维生命周期仍然千疮百孔：删除工作区只注销记录，把克隆留在磁盘上让宿主进程绊脚；成员能推送自己那条线，却没有协作手段把共享克隆其余部分的最新上游拉进同一棵共享树；每次全新引导都要为完整历史付费，即使只关心最近的提交；推送移动的是共享分支，却没有服务端记录谁在何时做了什么，管理员事后无法回答「是谁把这条分支推上去的」。

## 决策

四处小的服务端改动补齐了生命周期，每一处都延续既有的无 shell 运行器、凭据钉定与克隆失败静默移除契约：

- **删除移除克隆。** `collab/workspace.delete` 在记录注销后，现在也会删除仓库后端工作区所依托的克隆目录（递归且强制），因此删除工作区会关掉它的工作树，而不是把根留给宿主进程；删不动的克隆绝不影响删除——只警告（`collab clone removal ... failed`），记录删除照常成立。
- **抓取/同步端点。** `collab/workspace.fetch` 在不触碰检出的情况下把 origin 抓进已落定克隆：只动远端跟踪引用、清理过时引用，成员因此可以把共享仓库的最新上游拉进来，而不打扰任何会话的工作树或当前分支；也不提供硬重置路径。仅命名或仍在克隆的记录被拒绝（`collab-not-a-repository`）；git 失败折叠成 `collab-bad-request`。面板以仓库行的「同步」动作暴露它，并带瞬态确认提示。
- **浅克隆引导。** `collab` 设置命名空间的 `cloneDepth`（正整数）让新克隆执行 `git clone --depth <n>`，以截断历史为代价缩短首次传输；清空（或不设）即恢复完整历史克隆。GUI 设置页在克隆目录字段旁配了对应的深度字段。
- **推送审计线索。** 每次推送——试运行或真实推送——都会向 `<collabWorkspacesRoot>/audit/push.jsonl` 追加一行 JSON（工作区与操作者 id、操作者显示名、分支、试运行标记、已推送/已是最新，以及成功推送时的新远端 SHA 与对比链接）。写入是尽力而为的（失败只警告，绝不拖垮推送），线索位于 collab 根目录之下，因此比工作区删除活得更久，给管理员留下「谁在何时推了什么」的持久记录。

## 考虑过的备选方案

- **硬重置 / 破坏性同步。** 刻意推迟：只抓取让共享工作树对所有会话保持权威，而重置会以「只能怪远端」的方式丢弃另一个会话的未提交工作；若成员日后真需要破坏性移动共享树，那将是另一个显式带门禁的破坏性操作。
- **连仅命名的数据目录一起删除。** 推迟：仅命名的工作区按需物化数据目录，且可能仍被打开的会话引用；只移除已落定克隆让删除行为可预测，数据目录继续由宿主管理，与既有按工作区语义一致。
- **用审计表而非 JSONL 日志。** 线索目前是线性追加、无查询面的历史；根目录下每推送一行的 JSONL 保留成本为零、可随意消费，因此对一个有归属、有家的形式来说，这是正确的第一形态。
- **把抓取落进工作分支。** 否决：那会为一个「只靠远端跟踪引用就能回答」的读取移动共享树（或需要按会话的工作引用舞步）。

## 影响

- 删除仓库后端工作区现在真正释放其工作树；推过工作的用户已经把它发布到远端，想要回克隆的用户从同一 URL 重建，落进一个全新的以 id 命名的目录。
- 共享克隆在同步全程保持权威：不动工作树、不切分支、不重置——成员拉上游与推自己那条线同样轻巧。
- 浅克隆引导是遵循既有设置命名空间契约的操作员/默认旋钮，因此慢链实例可以不动创建语义就缩短克隆时间。
- 推送历史事后可查，且独立于工作区保留；读写删各处表面都对「哪些动作触碰了共享仓库」保持诚实。
