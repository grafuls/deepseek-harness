# Agent Note：collab 分支推送

Status: implemented

[English](2026-09-01-collab-push.md) | 中文

建立在[collab 仓库后端工作区](2026-08-29-collab-repo-backed-workspaces.zh.md)、[collab 异步仓库置备](2026-09-01-collab-async-repo-provisioning.zh.md)与[collab 按会话的工作分支](2026-09-01-collab-session-work-branches.zh.md)之上：本记录描述通过服务器 git 凭据对会话分支进行、需审批的服务端推送。

## 问题

按会话的工作分支把每个会话的提交隔离在自己的线上，但此前它们只存在于克隆本地：共享树从不推送，因此一个会话已完成的工作无法以独立拉取请求的形式到达仓库，操作员也没有服务端路径来发布它。推送需要认证（克隆用于私有仓库的同一操作员凭据）、一条覆盖远端历史的安全规则，以及一道人工门禁，以免误触或脚本化调用移动共享分支。

## 决策

面向成员的 RPC `collab/workspace.push` 在服务端执行推送：

- **审批门禁。** 除非请求携带显式 `confirm: true`（客户端在成员自己确认后才设置），否则端点以 `collab-approval-required` 失败关闭。门禁不按角色区分：任何成员都可以把自己的会话分支推到自己那条线上。推送使用与克隆相同的 `collabRepoCloner` 无 shell 运行器与 collab git 凭据。
- **默认线路。** 不带 `branch` 参数时端点推送当前检出的分支（`rev-parse --abbrev-ref HEAD`），因此会话若已分出自己的工作分支就推送该分支，停在主线上的检出则推送主线。游离检出（没有具名分支）会先以 `collab-bad-request` 拒绝。
- **非快进拒绝。** 触碰远端之前，先用 `ls-remote` 读取分支的线上远端尖点，再抓取该尖点（只动远端跟踪引用，工作树绝不动），除非抓取到的尖点是本地点点的祖先，否则以 `collab-push-rejected`（并点名远端提交）拒绝推送。推送本身从不带强制标记，因此在读取与推送之间移动的分支也会被 git 原子地拒绝。
- **试运行。** `dryRun: true` 会抓取并精确计算将移动什么（分支、基线、两端尖点、领先/落后数、链接）而不推送；对未经认证的读取失败保持公开，不降级。
- **凭据钉定。** 只有凭据钉在 origin 主机上时才发送服务器凭据；没有匹配凭据的 HTTPS origin 应答 `collab-credential-unavailable`。凭据经由与克隆相同的临时主机限定 git 配置（授权头）传输，调用结束后即删除，绝不出现在 URL 或任何存储值中。
- **署名。** 真实推送会把触发推送的成员 `user.name`/`user.email` 写入克隆本地配置（成员有身份时），此后在共享树里诞生的提交都带上该成员的署名；既有提交保留原始作者。
- **链接。** 对已知主线分支（`origin/HEAD`）的 HTTPS origin，响应携带 compare（`base...branch`）与「打开拉取请求」URL，让被推送的线路有人类的下一步。

## 考虑过的备选方案

- **带 `--force` 推送 / 自动删除注定失败的分支引用。** 否决：按会话分支的全部意义就在于安全、可评审的发布；强推或重置会无痕丢弃来自其他会话的远端提交。
- **用模型面向工具而非 GUI RPC。** 暂时否决：交互审批服务是回合作用域的（它要求开放中的代理回合，并把审计对写进该会话日志），因此回合之间的推送在那片面上没有审批入口。GUI 确认的 RPC 把门禁放在成员行动之处；日后可用同一 `pushWorkspaceBranch` 核心在其上加一层模型面向工具。
- **SSH 凭据作为推送传输。** 推迟：当下 HTTPS 令牌是唯一凭据种类；主机限定配置的管道是共享的，未来的 SSH 密钥种类可以接入同一门禁。
- **不抓取就解析远端尖点。** `ls-remote` 的 SHA 无法喂给 `git rev-list` 或 `git merge-base`，因为分叉更新后提交对象不在本地；条件抓取（仅当分支在远端存在时）让计数与快进门禁确定化。

## 影响

- 成员一次确认即完成推送：分支移动，响应点名新的远端提交并提供 compare/PR 链接，随后克隆仍停在同一分支（推送不改变检出）。
- 推送期间共享树正常工作：抓取只移动远端跟踪引用，因此会话的未提交编辑绝不被触碰。
- 私有主机推送需要把操作员凭据钉到该主机；否则端点大声拒绝（`collab-credential-unavailable`），而不是猜测。操作员契约与克隆一致：一对 `gitToken`/`gitHost`。
- 门禁之上的一切都对历史诚实：不快进、不强制、URL 中无凭据、无存储秘密。
