# Agent Note：collab 按会话的工作分支

Status: implemented

[English](2026-09-01-collab-session-work-branches.md) | 中文

建立在[collab 仓库后端工作区](2026-08-29-collab-repo-backed-workspaces.zh.md)、[collab 异步仓库置备](2026-09-01-collab-async-repo-provisioning.zh.md)与[collab git 状态可见性](2026-09-01-collab-git-state-visibility.zh.md)之上：本记录描述会话在仓库后端工作区内启动时，共享克隆被切换到的按会话分支。

## 问题

仓库后端工作区的克隆是一个共享检出，每位成员的会话都在其上操作。如果没有按会话的 git 概念，同一工作区的所有会话都会提交到同一条分支上，不同会话的工作堆在一起，无法区分提交各自属于谁，也无法把一个会话的工作作为独立拉取请求推送。工作区也没有任何钩子能区分会话彼此的活动。

## 决策

当会话在已落定的仓库后端协作工作区内创建时，collab API 订阅 `session/created`（全局作用域），把共享克隆切换到以该会话命名的分支：

- 从会话的规范工作目录出发，通过 collab 注册表的 `workspaceHolding`（规范克隆包含关系）解析所属工作区——与成员资格门使用的关系相同——因此克隆根或其任意子目录下的会话都会解析到自己的工作区，其他位置的会话解析不到任何工作区。
- 分支名为 `<workspace>-<session>`（两个组成部分都净化到 `[A-Za-z0-9._-]`），因此稳定、按会话唯一，并能在视图与侧边栏展示的 gitState 芯片中直接读出。
- 切换以 `git switch -c <branch>` 执行，分支已存在时回退为普通 `git switch <branch>`，因此重新创建或重新挂接的会话会回到自己那条线，而不会开出第二条或重置第一条。两种动作都经由共享的无 shell `gitCloneRunner`，并受同一个五秒状态读取超时约束。
- 分叉即发即忘：成功记 debug 日志，任何失败记 warn 日志——绝不放慢或破坏会话创建。每个守卫都是静默空操作——仓库后端工作区之外的会话、仍在克隆中的工作区、仅命名工作区或不可用的克隆都保持检出不变。
- 切换就是全部机制：分支只是共享树上的标签，主线分支（创建时克隆的默认分支）绝不因分叉而改动。订阅通过 `ctx.effect` 注册，随 collab 网关一起销毁。

## 考虑过的备选方案

- **在 `collab/workspace.open` 时分叉。** 区块的「新建会话」先打开工作区再启动会话，因此在 open 时分叉发生在会话 id 存在之前，无法按会话命名；而且每次普通工作区浏览都会分叉。否决：会话 id 是分支的身份，只有会话级钩子带得上它。
- **在工作区宿主的 `attachSession` 里分叉。** Host 实体在会话 cwd 落入工作区路径下时知道有会话加入，但把 collab 专属的 git 行为放进去会让 workspace 包与克隆模型耦合；collab API 拥有克隆契约，并通过 `workspaceHolding` 拿到同一事实。出于所有权而非可达性否决。
- **在会话第一次 git 写入时惰性分叉。** 没有可观察的「第一次写入」事件，而且在工作中途切换只有干净可合时才把未提交编辑带到另一条分支。否决：会话启动前切换是确定的，事后切换不是。

## 影响

- 仓库后端工作区里的每个会话都有自己的线：提交（以及后来的推送）留在 `<workspace>-<session>` 上，工作区主线分支不动。gitState 芯片已经渲染分支，因此每条按会话的线对所有成员无需终端即可见。
- 重新创建或重新挂接会话是幂等的：分叉的「创建或切换」回退会把检出移到现有分支而不重置它，因此会话已提交的工作得以保留。
- 分叉刻意是渐近的——`session/created` 宣告启动异步切换，最开始的几毫秒内运行 git 的会话可能短暂看到上一条分支。健康检出上窗口只有几毫秒，且绝不影响创建。
- 两个会话仍然共享一个工作树：分支隔离的是历史而非未提交文件，因此某位成员的未提交编辑对下一个切换的会话可见。共享树覆盖感知与推送阶段一起推迟，不在此解决。
- 非 collab 会话（家目录会话、克隆外的子代理工作）与仅命名工作区里的会话永不分叉——克隆包含守卫是唯一的门，因此省略 collab 覆盖层的单用户配置完全不受影响。
